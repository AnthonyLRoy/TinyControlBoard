# UART Protocol Reference

This document summarizes the current UART protocol shared between the ESP32 firmware and the Raspberry Pi scripts.

Primary source:

- [lib/protocol/uartProtocol.hpp](../lib/protocol/uartProtocol.hpp)

Related implementations:

- [lib/hal/uart/serial.cpp](../lib/hal/uart/serial.cpp)
- [scripts/rpi/home/antho/uart5_listener.py](../scripts/rpi/home/antho/uart5_listener.py)
- [scripts/rpi/home/antho/heartbeat_sender.py](../scripts/rpi/home/antho/heartbeat_sender.py)

## 1. Packet Format

Packets use a variable-length payload.

Layout:

| Byte Offset | Field | Size |
|---|---|---:|
| 0 | start byte | 1 |
| 1 | protocol version | 1 |
| 2 | source app | 1 |
| 3 | message type | 1 |
| 4 | sequence | 1 |
| 5-6 | command ID | 2 |
| 7 | payload length (`N`) | 1 |
| 8..7+N | payload | `N` |
| 8+N | checksum | 1 |

Current constants:

- start byte: `0xAA`
- protocol version: `0x01`
- command-packet size: `19` bytes (`N = 10`)
- maximum packet size: `69` bytes (`N = 60`)

## 2. Message Structure

The in-memory firmware struct is `UartMessage`.

It contains:

- `startByte`
- `version`
- `srcApp`
- `msgType`
- `sequence`
- `commandId`
- `params[5]`
- `nowPlayingText` / `nowPlayingLen`
- `trackElapsedSec` / `trackDurationSec` / `trackIsPlaying`
- `checksum`

Reference:

- [lib/protocol/uartProtocol.hpp](../lib/protocol/uartProtocol.hpp)

## 3. Message Types

Current message types are:

| Name | Value |
|---|---:|
| `MSG_COMMAND` | `0x01` |
| `MSG_STATUS` | `0x02` |
| `MSG_ACK` | `0x03` |
| `MSG_NACK` | `0x04` |
| `MSG_NOW_PLAYING` | `0x05` |
| `MSG_TRACK_PROGRESS` | `0x06` |

`MSG_TRACK_PROGRESS` carries five bytes: elapsed seconds (`uint16` little-endian),
duration seconds (`uint16` little-endian), and an `isPlaying` byte (`0` or `1`).

## 4. Application IDs

Current application IDs are:

| Name | Value |
|---|---:|
| `APP_ESP32` | `0x01` |
| `APP_PI` | `0x02` |

## 6. Checksum

The checksum is the sum of bytes `1` through `7 + N`, modulo 256. It includes the
payload-length byte and excludes the start byte and checksum itself.

Reference:

- [scripts/rpi/home/antho/uart5_listener.py](../scripts/rpi/home/antho/uart5_listener.py)

## 7. Current Pi Script Expectations

The Pi listener currently expects messages such as:

- shutdown,
- next/previous track,
- play/pause,
- stop,
- skip forward/back,
- rotary action,
- toggle meter,
- toggle cover view.

The Pi-side script interprets some commands directly and some as command-plus-parameter combinations.

Examples:

- `CMD_ROTARY_ACTION` uses parameter 0 for direction,
- `CMD_TOGGLE_METER` uses parameter 0 for enabled or disabled,
- `CMD_TOGGLE_COVER_VIEW` uses parameter 0 for enabled or disabled,
- `CMD_TOGGLE_DISPLAY` is generated by firmware with parameter 0 or 1.

## 8. Heartbeat

Heartbeat command ID is:

- `CMD_SYS_HEARTBEAT = 0x0003`

Current firmware compatibility note:

- the firmware also still accepts legacy heartbeat command `0x9999`.

Reference:

- [lib/app/ControlBoard.cpp](../lib/app/ControlBoard.cpp)

## 9. Current Practical Limitations

- The protocol reference is centralized, but some older macro aliases still exist in the header.
- The firmware actively reacts to heartbeat messages, but other incoming Pi-originated messages are not yet deeply handled in `ControlBoard`.
- The Pi scripts and firmware should be kept aligned on command IDs and parameter semantics.
